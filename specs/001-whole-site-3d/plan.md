# Implementation Plan: Whole-Site 3D Experience

**Branch**: `001-whole-site-3d` | **Date**: 2026-11-09 | **Spec**: [spec.md](./spec.md)

**Input**: Feature specification from `/specs/001-whole-site-3d/spec.md`

## Summary

Reface mairp.ai as an immersive whole-site 3D experience: one lazy-loaded, persistent
client island (React 19 + react-three-fiber) mounted in the Astro layout renders an
original mairp-branded "fabric room" environment whose in-world screens display the
site's real content (from the existing Astro content collections). Astro keeps
pre-rendering complete static HTML for every URL (router of record, SEO, sitemap,
fallbacks); the island adds camera-rig room navigation synced 1:1 to real URLs via the
History API. Mechanics (boot sequence, SHOTS-style camera rig, CSS3D live-HTML screens,
CRT aesthetic, N8AO+AgX postprocessing, synthesized audio) are adapted from the
reference demo at `/root/little-big-questions/room-viewer`; no demo content/assets ship.

## Technical Context

**Language/Version**: TypeScript (Astro strict) for site code; JSX/TSX for the island. Node ≥22.

**Primary Dependencies**: Astro ^7.3.5 (existing), @astrojs/react ^7.1.5 + react/react-dom ^19 (new renderer),
three pinned exact (0.186.x), @react-three/fiber ^9, @react-three/drei ^10,
@react-three/postprocessing ^3 (installed as a set). No @vitejs/plugin-react added manually.

**Storage**: N/A — content stays in existing Astro content collections (`src/content/`)
and `src/lib/site.ts`; no new persistence. Per-route Room Payloads ship as prerendered
same-origin JSON documents (e.g. `/rooms/<route>.json`, `prerender = true`) fetched by
the island at boot — never inlined into first-paint HTML (FR-016).

**Testing**: existing `astro check` (TS strict), linkinator, Lighthouse CI (lighthouserc.json,
≥0.95 × 4 categories), plus manual per-route 3D/fallback walkthroughs (quickstart.md);
vitest-style unit tests optional for payload-shape validation.

**Target Platform**: static output to Cloudflare Workers (ASSETS binding); browsers with
WebGL2 (desktop first), graceful flat fallback elsewhere.

**Project Type**: static web site + one client island.

**Performance Goals**: LHCI ≥0.95 on `/`, `/services/svc-agentic-netops/`, `/about/` for
performance/accessibility/best-practices/SEO; first-paint payload unchanged vs baseline
(zero three.js before primary content); 3D budget ≤ ~300 KB gz JS deferred; scene usable
within 10 s (target) / 20 s (hard ceiling) of landing incl. boot on a mid-range laptop
(SC-009), with key content progressively readable during boot (FR-003).

**Constraints**: strict CSP (`script-src 'self'`, exactly one hash-pinned inline script —
csp-hash.mjs fails the build otherwise; no CDN fetches: draco/meshopt decoders and any
HDRI self-hosted); `inlineStylesheets: 'never'`, `cssCodeSplit: false`, `trailingSlash:
'always'`; claim→evidence rules from DECISIONS.md; repos.yaml read-only (generated by
portfolio-sync); Twin chat/Turnstile, ThemeToggle, CopyButton keep working. **Content
neutrality (FR-015/SC-008, constitution P5): the demo repo contributes aesthetics and
mechanics only — every string/asset in 3D surfaces must trace to mairp-owned sources
(content collections, site.ts CV/bio data, GitHub portfolio data); no demo topics,
stories, editorial framing, branding, mascots or copy may ship; content-source audit
gate required.**

**Scale/Scope**: 10 routes (home, 7 services, about, 404 — 404 stays static), 9 mountable 3D rooms (the 7 service rooms share one template), ~5 content collections, one
persistent 3D island. Environment: procedural in-code "fabric room"; authored GLB is an optional later swap (see research.md R7).

### Source Code (repository root)

```text
src/
├── layouts/Base.astro            # mounts the persistent island (client:only, post-LCP)
├── pages/                        # unchanged routes; each exposes its prerendered
│   ├── rooms/[route].json.ts     # NEW: per-route Room Payload JSON (prerendered, FR-016)
│   │                             # payload endpoint; pages mount the island WITHOUT payload props
├── content.config.ts             # unchanged schemas
├── lib/
│   ├── site.ts                   # unchanged data
│   └── room-payload.ts           # NEW: builds per-page island payloads from collections
├── components/
│   └── RoomIsland.astro          # NEW: thin wrapper rendering the React island
├── islands/room3d/               # NEW: the 3D island (lazy, code-split)
│   ├── Room3D.tsx                # root: Canvas + boot gating + fallback decision
│   ├── boot/                     # boot overlay glue (useProgress → pre-JS #boot screen)
│   ├── rig/CameraRig.tsx         # SHOTS registry + bounded CameraControls
│   ├── rooms/                    # one module per room (home, service, about, …)
│   ├── screens/                  # CSS3D portal screens + content components
│   ├── fx/                       # postprocessing, CRT-style material, theme bridge
│   └── audio/                    # optional synthesized cues (default muted)
├── styles/tokens.css             # unchanged (island reads CSS vars)
public/
├── assets/models/                # NEW: compressed mairp GLB + self-hosted decoders
└── boot (inline in Base layout)  # pre-JS boot screen (from demo pattern)
```

**Structure Decision**: single Astro project; the island lives under `src/islands/room3d/`
and is only imported by the `RoomIsland.astro` wrapper, keeping three.js out of every
non-island import graph. No backend changes; per-route payload JSON endpoints (FR-016)
plus optional static JSON endpoints for lazy heavy content.
